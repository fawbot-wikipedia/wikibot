# Cewbotが解消した仮リンクのうち赤リンクに戻ったものの抽出 設計

使い方は [README](README.md) を参照。この文書は現在の仕様をまとめたもので、実装を変えたら合わせて更新する。

## 目的

日本語版ウィキペディアの [特別:投稿記録/Cewbot](https://ja.wikipedia.org/wiki/特別:投稿記録/Cewbot) のうち、要約が「解消済み仮リンク」で始まる編集（仮リンクを内部リンクに置き換えた編集）を対象に、置き換え先のページが現在存在しない（赤リンク）、または転送先のなくなった転送ページ（壊れた転送）になっていて、ページの最新版にも同じ内部リンクが残っているものを一覧にする。対象は既定で記事名前空間（0）とTemplate名前空間（10）。

例: [エミー・ネーターの版 90950554](https://ja.wikipedia.org/w/index.php?oldid=90950554)（2022-08-13 日本時間）で Cewbot が `{{仮リンク|ニコライ・チェボタリョフ|en|Nikolai Chebotaryov}}` を `[[ニコライ・チェボタリョフ]]` に置き換えた。リンク先は「ニコライ・チェボタレフ」への転送ページだったが、2025-12-21に「転送先がないリダイレクト」として削除され、最新版にもリンクが残っている。

## モジュール構成

| ファイル | 内容 |
|---|---|
| `cli.py` | コマンドラインの入口。引数の解析と、件数の概要の表示。`__main__.py` から呼ぶ |
| `pipeline.py` | 処理の流れ。編集の絞り込み、リンク先の集計、候補の追加、最終判定、最新版での分類、出力 |
| `report.py` | JSONの出力 |
| `paths.py` | 既定の置き場所（キャッシュ・ダンプ・出力）。いずれもこのパッケージの直下 |
| `sources/api.py` | APIの呼び出し（投稿記録、差分、削除・移動の記録、リンク先の状態、最新版の本文） |
| `sources/dump.py` | `page.sql`・`redirect.sql` の取得・解析と、リンク先の一次判定 |
| `sources/cache.py` | SQLiteのキャッシュ |
| `sources/user_agent.py` | APIとダンプの要求に付ける User-Agent |
| `parsing/summary.py` | 編集要約の判定と、リンク先の取り出し |
| `parsing/titles.py` | ページ名の正規化（比較用のキー） |
| `parsing/wikitext.py` | 本文の内部リンク・仮リンクの抽出、差分表からの「増えた内部リンク」と置換前の仮リンクの拾い出し |

依存の向きは一方向にする。`parsing/` は通信もファイルの読み書きもせず、`parsing/` の外のモジュールに依存しない。`sources/` は `parsing/` と `paths.py` を使う。`pipeline.py` は `sources/`・`parsing/`・`report.py` を使う。`cli.py` は `pipeline.py` を呼び、引数の既定値に `paths.py`、件数の表示に `report.py` の分類名を使う。

APIの呼び出しは `wikiutil.mediawiki.MediaWikiSession`、ダンプの取得は `wikiutil.dumps`、仮リンクの引数の解析は `wikiutil.ill.parse_ill_template` を使う。APIとダンプの要求には、ツール名と連絡先を示す User-Agent（`sources/user_agent.py` の `USER_AGENT`）を付ける。

## 取得元の使い分け

| 手順 | 取得元 | 理由 |
|---|---|---|
| Cewbotの投稿記録 | API | 1要求500件で約1,800要求。2回目からは差分だけで済む。ダンプでは `stub-meta-history`（約10.5 GB）の全版を走査する必要があり、重いうえ最大1か月古い |
| 要約が切れた編集のリンク先 | API（`action=compare`） | その編集の差分だけを1要求で取れる。結果は版ごとに永久にキャッシュする |
| リンク先の存在・転送（一次判定） | ダンプ（`page.sql.gz`・`redirect.sql.gz`） | リンク先は数十万件になり、APIでは数千要求かかる |
| ダンプ作成後の削除・移動 | API（`list=logevents`） | ダンプの実行日以降の記録だけを取る |
| 最終判定とページの最新版 | API | 候補に絞った後なので要求は少ない。「現時点」の状態は必ずAPIで確かめる |

## 処理

### 1. 対象編集の取得

- `list=usercontribs`（`ucuser=Cewbot`、`uclimit=max`、名前空間は指定しない）で投稿記録を新しい順に取得し、要約が `^(bot: )?解消済み仮リンク\[\[` に一致する編集をキャッシュに保存する。
  - 2016〜2020年ごろの要約は `bot: ` で始まるので、それも対象にする。
  - 「解消済み仮リンク」の直後が `[[` であることを条件にして、利用者ページの「…作業の報告」を除く。
  - 要約が隠された（`commenthidden`）編集は判定できないので除き、件数をログに出す。
- 初回は全期間を取得し、要求ごとに再開位置（`uccontinue`）を保存する。止まった場合は次回その位置から再開する。最後まで取得した後は、保存済みの最新時刻（`ucend`）より新しい編集だけを取得する。同じ revision ID は1件にまとめる。
- キャッシュは常に全期間・全名前空間で持ち、`--namespace`・`--since`・`--until` は後で絞るだけにする。日付は日本時間で比べる。
- APIの要求には `maxlag=5` を付け、混雑の応答（`maxlag`）なら `Retry-After` だけ待って再試行する。ページ名を50件並べるとURLが長くなるため要求はPOSTで送り、読み取りだけなのでPOSTも一時的な失敗のときに再試行する。

### 2. 置き換えたリンク先

- 要約の「解消済み仮リンク」と「を内部リンクに置き換えます」（2016年ごろは「…置き換える」）の間の `[[リンク先|表示名]]` からリンク先を取り出す。表示名にマークアップ（`<sub>`・`<br>`・`'''`）や注記「(Local page title contains …)」があってもよい。同じリンク先は1件にまとめる。
- 「を内部リンクに置き換え」がない要約は、長さの上限（255バイトだった時期）で切れているとみなす。その編集の差分（`action=compare`、`fromrev=<版>`、`torelative=prev`）の差分表から、消えた側の行と増えた側の行を取り出し、増えた側にだけある内部リンク（数の差）を置き換え先とする。
  - Cewbotが仮リンクの第1引数と違う名前でリンクを入れる場合があるため、第1引数との一致は条件にしない。
  - 変更された行に含まれていただけで仮リンクのまま残ったもの（例: 版 62396875 の「ジョージ・レノックス (1737-1805)」）は拾わない。
  - 増えた内部リンクがない、または解消された仮リンクの数より多い場合は、版の番号をログに出す。増えた内部リンクがなければ、要約の閉じたリンクを使う。
  - 版の本文が削除・版指定削除などで見られない（`missingcontent`・`nosuchrevid`・`permissiondenied`）場合は、版の番号をログに出し、要約の閉じたリンクを使う。
- 同じページ・同じリンク先に複数の編集がある場合は、最も新しい編集を代表にする。

### ページ名の正規化

`_` を空白にし、空白をまとめ、HTMLの文字参照を戻し、`#節` と先頭の `:` を除き、名前空間接頭辞（正式名と別名。`meta=siteinfo` から取る）を番号にそろえ、名前の先頭1文字だけを大文字にする。`wikiutil.mediawiki.title_key` は全体を `casefold` するので使わない。Pythonの `str.upper` がMediaWikiと違う文字では一次判定の照合に失敗するが、その場合は「ページがない」として候補に入り、最終判定のAPIで正しく判定されるので、結果は誤らない。

### 3. 一次判定（ダンプ）

- `page.sql.gz`・`redirect.sql.gz` のダンプ日は、`jawiki-latest-<ファイル名>-rss.xml` に書かれた実行ディレクトリから決める（`Last-Modified` は実行の開始日より後になりうるため使わない）。2つのファイルの実行日が違えばエラーにする。日付付きのURLから取得し、`dumpstatus.json` のsha1と照合する。
- `page` を全件メモリーに持たないよう、リンク先の集合と照らし合わせながら `page.sql` を2回、`redirect.sql` を1回読む。`INSERT` 文の値は正規表現で読み、文字列のエスケープと `NULL` を戻す。
- 候補にするもの:
  - ページがない（赤リンクの候補）
  - 転送ページで、転送先のページがない（壊れた転送の候補）
  - 転送ページだが転送表に行がない（判定できないので候補に入れて、APIで確かめる）
- 候補にしないもの: 通常のページ、転送先のある転送ページ（二重転送を含む）、他のウィキへの転送（`rd_interwiki` が空でない）。
- ダンプの実行日の0時（UTC）以降の `delete/delete`・`move/move`・`move/move_redir` の記録を取得し、リンク先、または転送ページの転送先と同じ名前（移動は移動元）の記録があれば候補に加える。
- ダンプ作成後に作られたページは、ダンプにないので自動的に候補に入り、最終判定で除かれる。
- ダンプ作成後に転送ページの転送先が書き換えられた場合は、記録に残らないため拾えない。

### 4. 最終判定（API）

候補を `prop=info`（`redirects` 指定）で50件ずつ問い合わせる。`missing` か長さ0なら赤リンク、転送ページで転送先が `missing`・`invalid` なら壊れた転送とする。それ以外（作成・修復されたもの）は除き、無効なページ名は件数と名前をログに出して除く。

### 5. 最新版での分類（API）

- 候補を含むページの最新版を `prop=revisions`（`pageids` 指定）で50件ずつ取得し、現在のページ名と名前空間を使う。削除されたページや対象外の名前空間へ移動されたページは除き、件数をログに出す。
- コメント・`<nowiki>`・`<pre>` の中を除いた本文で、`[[…]]` 形式の内部リンク（テンプレート引数の中、画像の説明文の中、Templateの `<noinclude>` の中を含む。入れ子でも拾えるよう、リンクの開始 `[[名前` の後に `|` か `]]` が続くものを数える）と、仮リンク系テンプレート（「仮リンク」とその転送の「ill」「ill2」「illm」「Interlanguage link」「Interlanguage link multi」「link-interwiki」、および「日本語版にない記事リンク」。先頭1文字の大文字・小文字と `Template:` 接頭辞は区別しない）の第1引数を集める。差分からリンクを拾うときも同じ規則を使う。`{{Main|…}}` のようにテンプレートが作るリンクは数えない。

| 分類 | 判定 |
|---|---|
| 残っている（出力） | 同じリンク先への内部リンクがある（仮リンクもあってもよい） |
| 仮リンクに戻された（件数だけ） | 内部リンクはなく、第1引数が同じリンク先の仮リンクがある |
| リンクが消えた（件数だけ） | どちらもない |

Cewbotが第1引数と違う名前でリンクを入れた編集は、元の仮リンクに戻されても「リンクが消えた」に数えられる。参考の件数にしか使わないので許容する。

## 出力

`<出力先>/YYYYMMDD_HHMMSS/resolved_ill_redlinks.json`（日本時間の取得日時）。UTF-8で出力し、日本語はエスケープしない。JSONの構造は次のとおり。

- `schema_version`: JSON構造の版。初版は `1`。
- `generated_at`: 最終判定と最新版の確認を終えた時刻（ISO 8601、UTC）。出力先ディレクトリ名は同時刻の日本時間。
- `timezone`: 編集日付の表示に使うタイムゾーン（`Asia/Tokyo`）。
- `dump_date`: 一次判定に使ったダンプの日付。
- `filters.namespaces`: 対象の名前空間番号と名前。
- `filters.period`: 対象としたCewbot編集期間（`since`・`until`）。未指定の境界は `null`。
- `counts`: 分類ごとの出力件数（`still_redlink`・`broken_redirect`）と、最新版にリンクが残っていなかった参考件数（`restored_ill`・`link_removed`）、削除・対象外の名前空間への移動で除外したページの件数（`page_gone`）。
- `items`: 出力対象のリンク1件ごとのレコード。分類（`category`）、名前空間、ページ名とURL、リンク先とURL、置き換えた版のID・固定リンク・差分リンク・時刻・日本時間の日付、置換前の仮リンク（`original_ill`）と実際の表示文言（`wording`）、削除・移動の記録（`log_note`）を含む。元の仮リンクを特定できない場合、`original_ill` と `wording` は `null` とし、理由を `original_ill_error` に記録する。ページ名順、同じページ内ではリンク先の名前順に並べる。

## キャッシュ

`ill/resolved_redlinks/cache/cache.sqlite3`（`--cache-file` で変更可）。書き込みはトランザクションで行う。表の版（`schema_version`）が合わない、またはSQLiteとして読めない場合は、黙って使わずエラーにする。

| 表 | 内容 | 更新 |
|---|---|---|
| `edits`・`meta` | 置き換えの編集、取得済みの最新時刻、初回取得の再開位置と完了したか | 新しい編集を追記する。`--refresh` で作り直す |
| `diff_links` | 要約が切れた編集の、差分から拾ったリンク先 | 版の内容は変わらないので消さない |
| `diff_ills` | 編集で置換された仮リンクテンプレート | 版の内容は変わらないので消さない |
| `log_entries` | 名前ごとの最後の削除・移動の記録と、確かめた時刻 | ダンプ実行日より前に確かめたものは問い合わせ直す。ダンプ作成後の記録は毎回取得した一覧を優先する |

最終判定と最新版の確認の結果はキャッシュしない。

## テストの観点

- 要約の判定（`bot: ` の有無、作業報告の除外）、リンク先の取り出し（マークアップ・注記・重複・切れた要約）。
- ページ名の正規化（先頭1文字だけの大文字化、名前空間の別名、ダンプのページ名との一致）。
- 差分表からの「増えた内部リンク」の拾い出し（残った仮リンクを拾わない、第1引数と違う名前も拾う）。
- SQLの値の解析（エスケープ、`NULL`）と一次判定（不存在・壊れた転送・転送表にない転送・他のウィキへの転送・二重転送）。
- 投稿記録の初回取得の再開と、完了後の差分取得。
- 最終判定、最新版での分類、削除・移動の記録の再利用、JSONの構造・値、差分からの元の仮リンクと表示文言の抽出。
